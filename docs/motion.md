## Cycle de vie

`app.ts` est chargé une seule fois. `astro:page-load` détruit d’abord les anciens propriétaires, puis initialise une page. `astro:before-swap` nettoie la page sortante et transmet la préférence au document entrant. Pas de `ScrollTrigger.killAll`. Une importation Three tardive vérifie que la page est encore vivante. Le menu et chaque formulaire/lab ont un AbortController distinct. Les poses sont déterministes, sans `Math.random`.

Un IntersectionObserver commun initialise les révélations, titres, scènes de services, masques de projets et étapes de méthode seulement à leur entrée dans l'écran. Les titres hors écran restent dans leur HTML initial ; les scènes cachées par la composition mobile ne sont pas animées. Les animations différées sont rattachées au contexte GSAP local pour être réversibles. ScrollTrigger est conservé pour les fragments liés à la progression du défilement.

La scène prépare ses shaders avec `renderer.compileAsync` dans une tâche distincte, seulement lorsqu'elle approche de l'écran. Le ticker démarre après cette préparation ; `data-ready` n'est posé qu'après un véritable rendu. Le SVG reste visible pendant l'attente. La perte du contexte interrompt le ticker et invalide les préparations en cours ; sa restauration relance la compilation. La destruction annule aussi les tâches différées. Sans `KHR_parallel_shader_compile`, le pilote peut encore bloquer une partie de la compilation : l'appel asynchrone ne garantit pas le même gain sur tous les GPU.

Le script inline du head calcule la préférence avant l’affichage. `auto` respecte `prefers-reduced-motion`, `reduced` supprime les mouvements, `off` arrête aussi les boucles. Changer la préférence reconstruit proprement les propriétaires et est enregistré localement ; aucune donnée n’est transmise. Pas d’écran de chargement et aucun masquage général du contenu.

L'absence de WebGL, une erreur de compilation ou la perte du contexte produisent un repli SVG. Aucun bloom, texture externe ou vidéo automatique. La présence du canvas et ses changements réels font l’objet d’un test séparé des captures immobiles.

## Budget de livraison

Au build vérifié, le module Three séparé représente 537 265 octets bruts, 109 065 Brotli ou 133 028 gzip. Le script principal représente 48 229 octets Brotli (53 399 gzip) ; les deux polices WOFF2 représentent ensemble 47 124 octets. Budgets de maintenance : module 3D ≤150 Ko gzip, script initial ≤65 Ko gzip, polices ≤55 Ko ; aucune vidéo automatique. L'alerte Vite sur le chunk 3D brut supérieur à 500 Ko reste visible : le découpage dynamique existe déjà, l'alerte n'est pas masquée.

L'éclairage final utilise HemisphereLight et deux lumières directionnelles avec un matériau Phong. Il évite la génération/convolution d'une carte d'environnement au démarrage, identifiée comme coûteuse dans la première mesure Lighthouse. Cette optimisation s'applique à tous les visiteurs, pas uniquement aux tests.
